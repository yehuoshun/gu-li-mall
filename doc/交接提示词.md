## 6. 已知坑（血泪）

1. **语雀 create 只认数字 book_id**：em82l9 = `85213543`（namespace 会报 book not found）
2. **mcporter 大 JSON**：不要 shell 命令替换内嵌（触发 auto-correction 报 Unknown server）→ 用 python subprocess + `json.dumps(args)`
3. **`.idea/` 故意入库**（项目级字典 `dictionaries/project.xml` 共享拼写词汇）——不移除、不忽略（`.iml` 已忽略）
4. **老板常并发推送**：push 前先 `git fetch` + `git rebase origin/main`，被拒是常态
5. **课程旧代码错拼不沿用**：Enume→Enum、VAILD→VALID、INVAILD→INVALID、UNKNOW→UNKNOWN、ACCT→ACCOUNT
6. **md 表格追加行要与整表对齐**；语雀 API 偶发抖动 → 调用带重试
7. **`AutoConfiguration.imports` 是数据源基座唯一的注册入口，勿删**（`MybatisPlusAutoConfiguration` 只标 `@AutoConfiguration`，不参与包扫描）；缺它则分页/乐观锁/防全表/自动填充**静默失效**（编译启动都正常）
8. **删了源码也未必暴露**：Maven 不会清理 `target/classes` 里的旧资源 → 本地"照常能跑"是残留副本造成的假象；**验证前先 `clean`**
9. **`annotationProcessorPaths` 一旦显式声明，classpath 上的处理器不再被扫描** → lombok 必须一并列上，否则 `@Data/@Getter/@Slf4j` 全失效（报「找不到符号 log」）；MPJ processor 同理必须列上，否则 Chain 类静默不生成
10. **本仓库自己的模块不能写进 `annotationProcessorPaths`**（compile 阶段没有 jar，解析必失败）；跨 jar 的自动配置只能靠 7 里那份文件。**nameFix 方案的思路就是「把生成器发布到本地仓库，当第三方处理器用」**
11. **IDEA 的注解处理器配置是从 Maven 导入生成的**（`.idea/compiler.xml` 按模块生成 profile）：改完 pom 必须 **Reload Maven Project**，否则 profile 里只有 lombok → IDE 内不生成 Chain → 满屏「找不到符号 XxxChain」
12. **nameFix 不在 Central**：本地仓库必须先有 `icu/mhb/*/2.1.3-nameFix/`（`mvn install` fork 或用 `tmp/mpj-2.1.3-nameFix.zip`）；fork **只能用 JDK 8 编**（其 lombok 1.18.10 限制）
13. **沙箱 TLS**：出网走中间人代理，JDK cacerts 不认 → 构建要用系统 trustStore（见 `TOOLS.md` 与 `scripts/build-gu-li-mall.sh`）
